# นาวาน (Navan) — LINE OA Backend

Backend สำหรับแอปนาวาน: รับ webhook จาก LINE OA, เก็บรายชื่อสมาชิกที่กดเพิ่มเพื่อน,
เช็คสภาพอากาศ **เฉพาะคน เฉพาะพื้นที่ เฉพาะเวลา** แล้ว push แจ้งเตือนเรื่องฝน/กรีดยาง/
ใส่ปุ๋ยให้แต่ละคนตามเวลากรีดยางของเขาเอง (เช่น พ่อกรีดตีสี่ แม่กรีดตีหนึ่ง ก็จะได้แจ้งเตือน
คนละเวลากัน ไม่ใช่ broadcast รวมทุกคนพร้อมกัน)

## ภาพรวม flow ทั้งหมด

1. LINE Developers Console — ตั้งค่า channel + webhook
2. Deploy โค้ดนี้ขึ้น Render (ฟรี)
3. ตั้ง Webhook URL กลับไปที่ LINE Console
4. สมัคร TMD API key แล้วใส่ใน environment variables
5. ตั้งตัวเองเป็นแอดมิน (`ADMIN_LINE_USER_ID`)
6. ให้พ่อแม่/ครอบครัวเพิ่มเพื่อน OA แล้วแอดมินกรอกโปรไฟล์ให้ทีละคน (ดู "เริ่มกับพ่อแม่" ด้านล่าง)
7. ทดสอบ

---

## ขั้นตอนที่ 1: ตั้งค่า LINE Developers Console

1. เข้า https://developers.line.biz/console/ แล้วล็อกอินด้วยบัญชีเดียวกับที่สร้าง LINE OA
2. ถ้า OA ที่สร้างไว้ยังไม่มี **Messaging API channel** ผูกอยู่ ให้ไปที่
   LINE Official Account Manager (manager.line.biz) > เลือก OA ของคุณ >
   ตั้งค่า > Messaging API > เปิดใช้งาน (Enable) — ระบบจะสร้าง channel ให้อัตโนมัติ
   แล้วจะไปโผล่ใน Developers Console
3. ใน Developers Console เลือก channel ของ OA นี้:
   - แท็บ **Basic settings** → คัดลอก **Channel secret**
   - แท็บ **Messaging API** → เลื่อนลงไปออก **Channel access token (long-lived)** →
     คัดลอกค่านี้ (กดออก token ใหม่ได้ถ้ายังไม่มี)
4. ในแท็บ **Messaging API** เดียวกัน:
   - ปิด **Auto-reply messages** และ **Greeting messages** (ปิดที่ LINE Official
     Account Manager ก็ได้ เพื่อไม่ให้ชนกับบอทที่เราจะสร้าง)
   - เปิด **Use webhook** เป็น Enabled (ค่า Webhook URL จะเติมทีหลังในขั้นตอนที่ 3)

## ขั้นตอนที่ 2: Deploy ขึ้น Render (ฟรี)

1. สมัคร/ล็อกอินที่ https://render.com
2. Push โฟลเดอร์นี้ขึ้น GitHub repo ของคุณก่อน (private repo ก็ได้)
3. ใน Render: **New +** → **Web Service** → เชื่อมกับ GitHub repo ที่เพิ่ง push
4. ตั้งค่า:
   - **Build command:** `npm install`
   - **Start command:** `npm start`
   - **Instance type:** Free
5. ไปที่แท็บ **Environment** ของ service แล้วเพิ่มตัวแปรตาม `.env.example`:
   - `LINE_CHANNEL_ACCESS_TOKEN`
   - `LINE_CHANNEL_SECRET`
   - `TMD_API_KEY` (ใส่ทีหลังก็ได้ ถ้ายังไม่สมัคร)
   - `TMD_PROVINCE` (ค่ากลาง เผื่อ user ที่ยังไม่มีโปรไฟล์ของตัวเอง)
   - `ADMIN_LINE_USER_ID` (ดูวิธีหาค่านี้ในขั้นตอนถัดไป — ใส่ทีหลังได้ ต้อง deploy รอบแรกก่อนถึงจะรู้ userId ของตัวเอง)
6. กด Deploy รอสักครู่ จะได้ URL ประมาณ `https://navan-bot-xxxx.onrender.com`

## ขั้นตอนที่ 3: ตั้ง Webhook URL

กลับไปที่ LINE Developers Console > แท็บ Messaging API:

- ใส่ **Webhook URL** เป็น `https://<โดเมนจาก Render>/webhook`
- กดปุ่ม **Verify** — ถ้าเชื่อมสำเร็จจะขึ้น Success
- เช็คว่า **Use webhook** เป็น Enabled อยู่

## ขั้นตอนที่ 4: ต่อ TMD Weather API

1. สมัครสมาชิกที่ https://data.tmd.go.th เพื่อขอ API key
   (ขั้นตอนละเอียด/ค่าใช้จ่ายบางส่วนต้องเช็คหน้าเว็บโดยตรง เพราะบางหน้าบล็อกการดึง
   ข้อมูลอัตโนมัติไว้)
2. ใส่ค่าที่ได้ใน environment variable `TMD_API_KEY` บน Render
3. ตรวจสอบ endpoint/field จริงใน `lib/weather.js` (ฟังก์ชัน `normalizeForecast`)
   ให้ตรงกับ response จริงของ TMD หลังสมัครแล้ว — โค้ดตอนนี้เดาโครงสร้างไว้คร่าว ๆ
4. ถ้ายังไม่ใส่ `TMD_API_KEY` ระบบจะใช้ข้อมูลจำลอง (mock) แทน ทำให้ทดสอบ
   flow การแจ้งเตือนทั้งหมดได้ก่อนโดยไม่ต้องรอสมัคร API

## ขั้นตอนที่ 5: ตั้งตัวเองเป็นแอดมิน

คำสั่ง `/users` และ `/setuser` (ดูหัวข้อ "เริ่มกับพ่อแม่" ด้านล่าง) ใช้ได้เฉพาะ userId
ที่ตรงกับ `ADMIN_LINE_USER_ID` เท่านั้น เพื่อกันคนอื่นมาแก้ข้อมูลมั่ว:

1. เพิ่มเพื่อน OA ของตัวเองก่อน (ใช้ LINE ส่วนตัว)
2. เปิดหน้า Render > service นี้ > แท็บ **Logs** จะเห็นบรรทัด
   `เพิ่มผู้ใช้ใหม่: <ชื่อคุณ> (<userId>)` — copy ค่า `userId` (ขึ้นต้นด้วย `U`)
3. กลับไปที่แท็บ **Environment** เพิ่ม `ADMIN_LINE_USER_ID` เป็นค่าที่ copy มา แล้ว
   save (Render จะ redeploy ให้อัตโนมัติ)
4. ทดสอบพิมพ์ `/help` ในแชท OA — ถ้าบอทตอบรายการคำสั่ง แปลว่าใช้แอดมินได้แล้ว

## ขั้นตอนที่ 6: เริ่มกับพ่อแม่ (หรือใครก็ตามคนแรก ๆ)

1. ส่งลิงก์/QR เพิ่มเพื่อน OA ให้พ่อแม่ (เอาจาก LINE Official Account Manager หน้าแรก)
2. พอเขากดเพิ่มเพื่อน ระบบจะบันทึก userId + ชื่อไว้อัตโนมัติ (แต่ยังไม่ได้ตั้งค่าอะไร)
3. พิมพ์ `/users` ในแชท OA (ต้องพิมพ์จากบัญชีแอดมิน) เพื่อดูว่า userId ของพ่อ/แม่คืออะไร
4. **คุยกับพ่อแม่โดยตรง** (โทร/แชทส่วนตัว) เพื่อถามพิกัด GPS ของสวนยาง (หรือกาง Google Maps
   ช่วยปักหมุดให้), จังหวัด, และเวลาที่เขากรีดยางปกติ เช่น "ตีสี่" = 04:00
5. พิมพ์คำสั่งบันทึกโปรไฟล์ในแชท OA:
   ```
   /setuser <userId ของพ่อ> นครพนม 17.401,104.779 04:00
   /setuser <userId ของแม่> นครพนม 17.402,104.780 01:00
   ```
6. เสร็จแล้วพิมพ์ `/users` อีกรอบเพื่อยืนยันว่าโปรไฟล์ถูกบันทึกครบ

จากนี้ระบบจะเช็คให้อัตโนมัติทุก 30 นาที ถ้าใกล้เวลากรีดยางของแต่ละคน (ค่าเริ่มต้นคือ
1-2 ชม.ก่อนเวลา ปรับได้ที่ `ALERT_LEAD_MIN_MINUTES` / `ALERT_LEAD_MAX_MINUTES`) และฝนใน
จังหวัดของเขา ≥60% จะ push แจ้งเตือนไปหาเฉพาะคนนั้น

## ขั้นตอนที่ 7: ทดสอบ

- พิมพ์คำว่า **"สภาพอากาศ"** ในแชท OA (จากบัญชีใครก็ได้ที่ follow แล้ว) เพื่อเช็คว่าบอท
  ตอบกลับถูกต้อง — ถ้าคนนั้นมีโปรไฟล์แล้วจะใช้จังหวัดของเขาเอง ถ้ายังไม่มีจะใช้ `TMD_PROVINCE`
- อยากทดสอบ push อัตโนมัติเร็ว ๆ โดยไม่ต้องรอเข้าเงื่อนไขจริง ให้ตั้ง `tapTime` ของ
  user ทดสอบ (ผ่าน `/setuser`) ให้อยู่ในช่วง 60-120 นาทีข้างหน้าจากเวลาปัจจุบัน แล้วรอ
  รอบ cron ถัดไป (สูงสุด 30 นาที) หรือจะลดรอบ cron ใน `server.js` เป็น `*/2 * * * *`
  ชั่วคราวเพื่อทดสอบไว ๆ ก็ได้ ทดสอบเสร็จค่อยเปลี่ยนกลับ

## ข้อจำกัดของ Render free tier ที่ควรรู้

- เซิร์ฟเวอร์จะ "หลับ" ถ้าไม่มีคนเรียกใน ~15 นาที ทำให้ webhook แรกหลังจากหลับ
  อาจช้าไปสักพัก (cold start) — ถ้ากวนใจ ตั้ง uptime monitor ฟรี (เช่น
  UptimeRobot) ให้ ping `/` ทุก 10 นาทีได้
- ไฟล์ `data/users.json` (รายชื่อ + โปรไฟล์ของคนที่ follow) จะ**หายทุกครั้งที่ deploy
  ใหม่** เพราะดิสก์บน free tier เป็นแบบชั่วคราว — แปลว่าทุกครั้งที่ deploy ใหม่ต้อง
  `/setuser` ให้พ่อแม่ใหม่ด้วย! ใช้ได้สบายตอนทดสอบกับครอบครัวไม่กี่คน แต่พอจะขยาย
  จริงจัง แนะนำย้ายไปเก็บใน Render Persistent Disk, Supabase (ฟรี), หรือ Google
  Sheets ผ่าน API แทน
- **ข้อจำกัดของ TMD API ที่รู้อยู่แล้ว**: endpoint ที่ใช้ตอนนี้รับพารามิเตอร์เป็น
  "จังหวัด" เท่านั้น ไม่รองรับพิกัด GPS ตรง ๆ ดังนั้นความแม่นยำตอนนี้คือระดับจังหวัด
  ไม่ใช่ระดับแปลงสวนจริง ๆ (พิกัด GPS ที่เก็บไว้ใน `users.json` ยังไม่ถูกใช้คำนวณ
  สภาพอากาศ — เก็บไว้เผื่ออนาคตเปลี่ยนไปใช้ API ที่รองรับพิกัด)
- ระบบรองรับแอดมินได้คนเดียว (`ADMIN_LINE_USER_ID` ตัวเดียว) ถ้าจะให้มีหลายแอดมิน
  ต้องแก้โค้ดเพิ่ม

## โครงสร้างไฟล์

```
navan-line-bot/
├── server.js          # webhook handler + คำสั่งแอดมิน + cron scheduler
├── lib/
│   ├── users.js       # เก็บ/โหลด/อัปเดตโปรไฟล์ผู้ใช้ (province, lat, lon, tapTime)
│   ├── weather.js      # ดึงพยากรณ์ TMD (ตาม province) + ตรรกะตัดสินใจแจ้งเตือน
│   └── time.js         # แปลงเวลาเป็นโซนไทย + คำนวณนาทีก่อนถึงเวลากรีดยาง
├── data/users.json     # สร้างอัตโนมัติตอนรันจริง (ไม่ได้ commit)
├── .env.example
└── package.json
```
